The connector is configured once, through a readonly `SteamConfig` — everything the SDK
needs at runtime lives on that object.

## The connector

`SteamConnector` targets `https://api.steampowered.com` and carries your credentials:

<Steps>

1. Keep your [Steam Web API key](https://steamcommunity.com/dev) out of the source tree:

   ```dotenv title=".env"
   STEAM_API_KEY=your-steam-web-api-key
   ```

2. Hand it to a `SteamConfig`, and the config to a connector:

   ```php title="steam.php" "$_ENV['STEAM_API_KEY']"
   use Fkrzski\SteamApiSdk\SteamConfig;
   use Fkrzski\SteamApiSdk\SteamConnector;

   $connector = new SteamConnector(new SteamConfig(
       apiKey: $_ENV['STEAM_API_KEY'],
   ));
   ```

3. Reuse that one connector — it carries the key and the daily budget, so building a
   fresh one per call buys you nothing.

</Steps>

The key is appended to every request as the `key` query parameter, so you never pass it
per call. The endpoints Steam serves anonymously — `GetNumberOfCurrentPlayers`,
`GetGlobalAchievementPercentagesForApp` and `UpToDateCheck` — go out with it stripped back off.

## SteamConfig options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `apiKey` | `?string` | `null` | Your Steam Web API key. Leave it out to reach only the anonymous endpoints. |
| `rateLimitStore` | `?RateLimitStore` | `MemoryStore` | Where the daily request budget is tracked. |
| `language` | `?Language` | `null` | Language for endpoints that localise their payload. |
| `connectTimeout` | `?float` | `10.0` | Seconds to wait for a connection to Steam. |
| `requestTimeout` | `?float` | `30.0` | Seconds the whole request may take. |
| `tries` | `int` | `1` | Attempts per request, the first one included. |
| `retryInterval` | `int` | `0` | Milliseconds to pause before a retry. |
| `exponentialBackoff` | `bool` | `false` | Double the pause after every retry. |

<Aside type="note" title="Readonly, so replace rather than mutate">
`SteamConfig` is `final readonly` — to change a setting, construct a new config and a
new connector.
</Aside>

## Without an API key

A config built without one reaches the anonymous endpoints and nothing else. Every
other request raises `ApiKeyNotConfiguredException` before it leaves your process, naming
the request class that needed the key:

```php title="steam.php"
$connector = new SteamConnector(new SteamConfig);

$connector->stats()->currentPlayers(381210);  // sent
$connector->users()->summaries([$steamId]);   // ApiKeyNotConfiguredException
```

<Aside type="caution" title="A blank key is not the same as no key">
`new SteamConfig(apiKey: '')` throws where `null` is accepted. A blank string would
otherwise travel to Steam as `key=` and come back refused a round trip later.
</Aside>

## Default language

Steam localises the achievement and stat names it sends back through the `l` query
parameter. Set it once on the config rather than on every call:

```php title="steam.php" "language: Language::Polish"
use Fkrzski\SteamApiSdk\Enums\Language;

$connector = new SteamConnector(new SteamConfig(
    apiKey: $_ENV['STEAM_API_KEY'],
    language: Language::Polish,
));
```

A language passed to a call wins over the config, and endpoints that do not localise
anything never receive one:

```php
$connector->stats()->achievements($steamId, 381210);                    // polish
$connector->stats()->achievements($steamId, 381210, Language::English); // english
```

Steam's codes are Valve's own rather than ISO, so the
[`Language`](/php-steam-api-sdk/dto-reference#language) enum transcribes their table.

## Timeouts

Both are in seconds, and both fall back to Saloon's own defaults when left out:

```php title="steam.php" "connectTimeout: 3" "requestTimeout: 120"
$connector = new SteamConnector(new SteamConfig(
    apiKey: $_ENV['STEAM_API_KEY'],
    connectTimeout: 3,
    requestTimeout: 120,
));
```

`0` waits indefinitely, and a negative value throws `InvalidTimeoutException` as the config
is built. A request that runs out of either raises `SteamConnectionException`, like any
other request Steam never answered.

## Retries

Every request is sent once until `tries` says otherwise:

```php title="steam.php" "tries: 3" "retryInterval: 500" "exponentialBackoff: true"
$connector = new SteamConnector(new SteamConfig(
    apiKey: $_ENV['STEAM_API_KEY'],
    tries: 3,
    retryInterval: 500,
    exponentialBackoff: true,
));
```

`retryInterval` is in milliseconds and `exponentialBackoff` doubles it after each retry, so
the config above pauses 500 ms, then 1 s. Fewer than one try or a negative interval throws
`InvalidRetryException` as the config is built.

Only what can change by the next attempt is retried: Steam unreachable, a timeout, a `5xx`.
A `4xx` is thrown at once, and so is `SteamRateLimitException`, whether the budget ran out
locally or Steam answered `429`. Once the tries are spent, the last attempt's exception is
thrown. `sendAsync()` and `pool()` send every request once.

<Aside type="caution" title="Every attempt is a request">
Each retry spends one of the day's 100 000 requests: the budget counts a `5xx` like any
other answer.
</Aside>

## Rate limiting

The Steam Web API allows **100 000 requests per API key per day**. The connector
enforces this via [`saloonphp/rate-limit-plugin`](https://github.com/saloonphp/rate-limit-plugin)
and throws `SteamRateLimitException` once the budget is spent — locally, before a
request leaves your process. The exception carries the `Limit` that tripped:

```php
use Fkrzski\SteamApiSdk\Exceptions\SteamRateLimitException;

try {
    $connector->send($request)->dto();
} catch (SteamRateLimitException $e) {
    $seconds = $e->limit->getRemainingSeconds();
}
```

Steam bills that budget to the key, so a connector without one counts nothing locally. It
still raises the same exception when Steam itself answers `429`.

## Multiple API keys

The budget is tracked per API key, so one process — or one shared store — can serve
several keys without them draining each other's quota.

<Aside type="tip" title="Your key never reaches the store">
The limiter key is `SteamConnector:` plus a **SHA-256 hash** of the API key, so a shared
store holds counters, never credentials.
</Aside>

## Sharing the budget across processes

The default `MemoryStore` keeps its backing array static, so the budget is process-wide.
That is fine for a script, but every FPM or queue worker then gets a counter of its own
and the real quota can be overrun several times over.

Inject a shared store instead — any `Saloon\RateLimitPlugin\Contracts\RateLimitStore`
is accepted:

```php
$connector = new SteamConnector(new SteamConfig(
    apiKey: $_ENV['STEAM_API_KEY'],
    rateLimitStore: $store,
));
```

<Tabs syncKey="steam-rate-limit-store">
  <TabItem label="Redis (Predis)">
    ```php
    use Saloon\RateLimitPlugin\Stores\PredisStore;

    $store = new PredisStore(new Predis\Client());
    ```
  </TabItem>
  <TabItem label="Redis (ext-redis)">
    ```php
    use Saloon\RateLimitPlugin\Stores\RedisStore;

    $redis = new Redis();
    $redis->connect('127.0.0.1');

    $store = new RedisStore($redis);
    ```
  </TabItem>
  <TabItem label="PSR-16 cache">
    ```php
    use Saloon\RateLimitPlugin\Stores\PsrStore;

    // $cache is any Psr\SimpleCache\CacheInterface implementation.
    $store = new PsrStore($cache);
    ```
  </TabItem>
  <TabItem label="Filesystem">
    ```php
    use Saloon\RateLimitPlugin\Stores\FileStore;

    $store = new FileStore(__DIR__.'/storage/steam-rate-limit');
    ```
  </TabItem>
</Tabs>

<Aside type="caution" title="A per-process store is not a shared one">
`MemoryStore` and a `FileStore` on ephemeral disk both look fine in development and stop
working the moment you scale out. Pick a store every process genuinely reaches.
</Aside>
