Once you have a [configured connector](/php-steam-api-sdk/configuration), three concepts carry the
rest: the **`SteamId`** value object every request accepts, the **resources** you call on
the connector, and the readonly **DTOs** you get back.

## The `SteamId` value object

`SteamId` is the only accepted identifier across the SDK — no raw strings. Which
constructor you reach for depends on where the ID came from:

<Tabs syncKey="steam-id-source">
  <TabItem label="Verified ID">
    ```php
    use Fkrzski\SteamApiSdk\ValueObjects\SteamId;

    // Throws InvalidSteamIdException on anything but a 17-digit numeric ID.
    $id = SteamId::fromSteamId64('76561198000000000');
    ```
  </TabItem>
  <TabItem label="User input">
    ```php
    use Fkrzski\SteamApiSdk\ValueObjects\SteamId;

    // Returns null for anything that is not a SteamID64 or /profiles/<id> URL.
    $id = SteamId::tryFromInput('https://steamcommunity.com/profiles/76561198000000000');
    ```
  </TabItem>
  <TabItem label="Vanity URL">
    ```php
    use Fkrzski\SteamApiSdk\ValueObjects\SteamId;

    // A /id/<name> URL carries no Steam ID — pull the slug out and let Steam resolve it.
    $vanity = SteamId::extractVanityName('https://steamcommunity.com/id/gabelogannewell/');

    $id = $connector->users()->resolveVanityUrl($vanity);
    ```
  </TabItem>
</Tabs>

The underlying value is available as `$id->value` (or `(string) $id`), and two IDs
compare with `$id->equals($other)`.

<Aside type="caution" title="extractVanityName() never fails">
It extracts a slug, it does not validate one — anything that is not a `/id/<name>` URL
comes back unchanged. [`ResolveVanityUrlRequest`](/php-steam-api-sdk/api-reference#resolvevanityurlrequest)
is what rejects an unknown name.
</Aside>

<Aside type="note" title="JSON is a one-way trip">
`SteamId` implements `JsonSerializable`, so it encodes as a bare string, not a nested
object. Decoding is not symmetric — rebuild it with `SteamId::fromSteamId64()`.
</Aside>

## Sending requests

The connector groups every endpoint into a resource per Steam interface — `players()` for
`IPlayerService`, `users()` for `ISteamUser`, `stats()` for `ISteamUserStats`, `apps()` for
`ISteamApps`, `news()` for `ISteamNews`. Each method
sends the request and hands back the DTO, so nothing needs importing:

```php
$summaries = $connector->users()->summaries([$id]);
```

Behind every resource method sits a plain Saloon `Request`, still public and unchanged.
Build one yourself when you want the response rather than only the DTO, or a Saloon
feature that takes a request — `pool()` or `sendAsync()`:

```php
use Fkrzski\SteamApiSdk\Http\Requests\ISteamUser\GetPlayerSummariesRequest;

$response = $connector->send(new GetPlayerSummariesRequest([$id]));

$response->status();      // 200
$summaries = $response->dto();
```

The connector uses Saloon's `AlwaysThrowOnErrors`, so a non-2xx response fails before the
DTO is built — always as an SDK exception, never a Saloon one. The same holds when no
response comes back at all, through `send()`, `sendAsync()` and `pool()` alike. Which call
returns which DTO is in the [API reference](/php-steam-api-sdk/api-reference).

## Exceptions

Every SDK failure extends `SteamApiException`, so one catch handles them all:

```text frame="none"
SteamApiException                  (root, extends RuntimeException)
├── ApiKeyNotConfiguredException   No key on the config, and the request needs one.
├── AppNewsUnavailableException    No news published for the app, or unknown app.
├── AppNotFoundException           No Steam app carries the given app ID.
├── AppVersionUnavailableException No server version to check against, or unknown app.
├── InvalidApiKeyException         Steam refused the key: wrong, revoked, or absent.
├── InvalidRetryException          Fewer than one try, or a negative retry interval.
├── InvalidServerAddressException  Address is neither IPv4 nor IPv4:queryport.
├── InvalidSteamIdException        Malformed SteamID64.
├── InvalidTimeoutException        Negative timeout handed to SteamConfig.
├── ProfileNotPublicException      Profile, games list, groups, or stats are private.
├── StatsUnavailableException      Stats withheld: none exist, unknown app, or private profile.
├── SteamConnectionException       Steam never answered: timeout, DNS, TLS, refused connection.
├── SteamRateLimitException        Daily 100k quota reached; exposes the offending Limit.
├── SteamUserNotFoundException     Vanity URL unresolved or profile missing.
└── TooManySteamIdsException       More than 100 IDs in a batch request.
```

Catch the leaf you care about, or the root to handle every SDK failure uniformly:

<Tabs syncKey="steam-error-handling">
  <TabItem label="Catch everything">
    ```php
    use Fkrzski\SteamApiSdk\Exceptions\SteamApiException;

    try {
        $summaries = $connector->users()->summaries([$id]);
    } catch (SteamApiException $e) {
        // Every SDK failure lands here — auth, privacy, quota, transport.
        $logger->error($e->getMessage(), ['status' => $e->getCode()]);

        $summaries = [];
    }
    ```
  </TabItem>
  <TabItem label="Catch specific">
    ```php
    use Fkrzski\SteamApiSdk\Exceptions\ProfileNotPublicException;
    use Fkrzski\SteamApiSdk\Exceptions\SteamRateLimitException;

    try {
        $library = $connector->players()->ownedGames($id);
    } catch (ProfileNotPublicException) {
        $library = [];  // expected — a hidden library is not an error worth logging
    } catch (SteamRateLimitException $e) {
        $logger->warning(sprintf('Steam quota spent, retry in %ds.', $e->limit->getRemainingSeconds()));

        throw $e;
    }
    ```
  </TabItem>
</Tabs>

The [API reference](/php-steam-api-sdk/api-reference) notes which request throws which exception.

### Inspecting the failed response

Exceptions raised from an HTTP failure carry the response that produced them, and
their code is the HTTP status:

```php {6,7}
use Fkrzski\SteamApiSdk\Exceptions\SteamApiException;

try {
    $summaries = $connector->users()->summaries([$id]);
} catch (SteamApiException $e) {
    $e->getCode();          // 403
    $e->response?->body();  // raw Steam payload, or null when no response came back
}
```

A status the SDK gives no meaning of its own surfaces as the root `SteamApiException`, with
Saloon's `RequestException` on `getPrevious()`.

<Aside type="note" title="A null response is routine, not an edge case">
`response` is `null` for every failure raised before a request went out — a malformed
SteamID64, an oversized batch, the quota exhausted locally — and for one that went out and
got no answer, where the transport exception sits on `getPrevious()` instead.
</Aside>

### How statuses are mapped

Steam signals failure in two different ways, and the SDK reads both, along with the request
Steam never answers at all:

| Steam's answer | Exception |
| --- | --- |
| `400` + HTML naming the `key` parameter | `InvalidApiKeyException` (missing) |
| `401` or `403` + HTML naming the `key` parameter | `InvalidApiKeyException` (rejected) |
| `400` or `403` + JSON, on `ISteamUserStats` | `StatsUnavailableException` / `ProfileNotPublicException` / `AppNotFoundException` |
| `403` + `{}`, on `GetNewsForApp` | `AppNewsUnavailableException` |
| `401` or `403` not naming the `key` parameter | `ProfileNotPublicException` |
| `404` + JSON, on `ISteamUserStats` | `AppNotFoundException` |
| `500` + JSON `Failed to get appinfo`, on `GetSDRConfig` | `AppNotFoundException`, never retried |
| `429` | `SteamRateLimitException` |
| any other `4xx` / `5xx` | `SteamApiException`, a `5xx` once the [retries](/php-steam-api-sdk/configuration#retries) are spent |
| `200` with an empty, `success: 42` or `success: false` payload | `ProfileNotPublicException` / `SteamUserNotFoundException` / `AppVersionUnavailableException` / `InvalidServerAddressException` |
| `200` with `success: false` and a message the SDK does not recognise | `SteamApiException`, quoting Steam's message |
| no answer: a timeout, a DNS or TLS failure, a refused connection | `SteamConnectionException` with code `0`, once the [retries](/php-steam-api-sdk/configuration#retries) are spent |

`ApiKeyNotConfiguredException` has no row here: it is raised locally, so a request that
needs a key the config does not carry never reaches Steam at all.

Steam overloads `400` across unrelated causes. Key errors are the one case it answers
with HTML rather than JSON — that is what keeps a misconfigured key from surfacing as a
data problem. Which status a key error lands on is the endpoint's choice, not the SDK's:
`ISteamUser` reports an absent key as `400`, `GetBadges` and `GetSteamLevel` answer `403`,
and `GetCommunityBadgeProgress` answers `401`. Only `ISteamUser` separates an absent key
from a rejected one, so everywhere else it surfaces as rejected. A JSON `400` on
`ISteamUserStats` is endpoint-specific too: `GetSchemaForGame` is the one endpoint whose
`400` means nothing but an app ID Steam does not know, so it is the one that raises
`AppNotFoundException` from that status.

<Aside type="caution" title="Six endpoints answer ambiguously">
`GetPlayerAchievements` returns a byte-identical `Requested app has no stats` body for an app
without achievements and for a private profile, and `GetRecentlyPlayedGames` and
`GetCommunityBadgeProgress` return an empty payload both for a hidden profile and for a
SteamID64 that belongs to no account. `GetGlobalAchievementPercentagesForApp`, `UpToDateCheck`
and `GetNewsForApp` answer an app ID Steam does not know exactly like an app with nothing to
report: a `403` for a game without achievements, `success: false` for one without versioned
servers, and a `403` for an app whose news Steam does not publish. Every message names every
cause rather than guessing.
</Aside>

## Debugging

`debug()`, `debugRequest()` and `debugResponse()` are Saloon's. They register on the
connector, so every call after them is dumped, with the API key masked as `key=***`:

```php
$connector->debug()->users()->summaries([$id]);
```

```text frame="terminal" title="php steam.php" "key=***"
Saloon Request (GetPlayerSummariesRequest) -> array:6 [
  "connector" => "Fkrzski\SteamApiSdk\SteamConnector"
  "request" => "Fkrzski\SteamApiSdk\Http\Requests\ISteamUser\GetPlayerSummariesRequest"
  "method" => "GET"
  "uri" => "https://api.steampowered.com/ISteamUser/GetPlayerSummaries/v2/?key=***&steamids=76561197960435530"
  "headers" => array:1 [
    "Host" => "api.steampowered.com"
  ]
  "body" => ""
]
```

The default dumper is `symfony/var-dumper`, which the SDK suggests rather than requires:

```bash
composer require --dev symfony/var-dumper
```

<Aside type="caution" title="A missing dumper fails late">
Without it, `debug()` itself succeeds and the first request then dies on
`Class "Symfony\Component\VarDumper\VarDumper" not found`. Callables of your own passed to
`debugRequest()` and `debugResponse()` need nothing.
</Aside>

A callable passed to `debugRequest()` gets the same masked PSR request, and only that request
is masked. The `PendingRequest` beside it, the `Response` in `debugResponse()`, and
`debugRequest()` called on a request object rather than the connector all still reach the key.

## Testing

The connector is stock Saloon, so `MockClient` fakes it with no SDK-specific helper.
Mocks stay keyed by request class even when the call goes through a resource, and DTOs are
built from the fake, so assertions run against real DTOs:

<Tabs syncKey="php-test-runner">
  <TabItem label="Pest">
    ```php
    use Fkrzski\SteamApiSdk\Http\Requests\ISteamUser\GetPlayerSummariesRequest;
    use Saloon\Http\Faking\MockClient;
    use Saloon\Http\Faking\MockResponse;

    it('reads the persona name off a summary', function (): void {
        $mock = new MockClient([
            GetPlayerSummariesRequest::class => MockResponse::make([
                'response' => ['players' => [/* ... */]],
            ]),
        ]);

        $connector = new SteamConnector(new SteamConfig('test-key'));
        $connector->withMockClient($mock);

        $summaries = $connector->users()->summaries([$id]);

        expect($summaries[0]->personaName)->toBe('gabelogannewell');
    });
    ```
  </TabItem>
  <TabItem label="PHPUnit">
    ```php
    use Fkrzski\SteamApiSdk\Http\Requests\ISteamUser\GetPlayerSummariesRequest;
    use Saloon\Http\Faking\MockClient;
    use Saloon\Http\Faking\MockResponse;

    final class PlayerSummariesTest extends TestCase
    {
        public function test_it_reads_the_persona_name_off_a_summary(): void
        {
            $mock = new MockClient([
                GetPlayerSummariesRequest::class => MockResponse::make([
                    'response' => ['players' => [/* ... */]],
                ]),
            ]);

            $connector = new SteamConnector(new SteamConfig('test-key'));
            $connector->withMockClient($mock);

            $summaries = $connector->users()->summaries([$id]);

            $this->assertSame('gabelogannewell', $summaries[0]->personaName);
        }
    }
    ```
  </TabItem>
</Tabs>

<Aside type="caution" title="Reset the budget between tests">
`MemoryStore` keeps its backing array **static**, so the counter survives from one test
to the next and a long suite can trip `SteamRateLimitException` on its own. Clear it in
your setup hook.
</Aside>

<Tabs syncKey="php-test-runner">
  <TabItem label="Pest">
    ```php title="tests/Pest.php"

    beforeEach(fn () => MemoryStore::clear());
    ```
  </TabItem>
  <TabItem label="PHPUnit">

    ```php title="tests/TestCase.php"
    protected function setUp(): void

        parent::setUp();

        MemoryStore::clear();
    }
    ```
  </TabItem>
