A framework-agnostic PHP SDK for the [Steam Web API](https://steamcommunity.com/dev),
built on top of [Saloon](https://docs.saloon.dev/) v4. Every request returns a
strongly-typed value, a readonly DTO for most — you never touch raw JSON, and an answer
the SDK cannot read fails with an exception instead of passing as an empty list. It powers
the player profiles on [Dead by Stats](https://deadbystats.eu).

## Why php-steam-api-sdk

- **Fluent resources** — `$connector->players()->ownedGames($id)`, no request classes to import.
- **Past 100 Steam IDs** — `summaries()` and `bans()` cut a long list into concurrent requests.
- **Strongly typed** — PHP 8.5, PHPStan max, 100% type coverage.
- **Readonly DTOs** — immutable objects with `DateTimeImmutable`, never framework date wrappers.
- **Domain exceptions** — one hierarchy rooted at `SteamApiException`, carrying Steam's status
  and response whenever its answer is what failed.
- **Rate limit baked in** — the 100 000 requests/day quota is enforced per API key and resets at 00:00 UTC; `rateLimits` swaps in your own.
- **Timeouts and retries** — set once on `SteamConfig`; only a `5xx` or no answer at all is retried, since every attempt spends quota.
- **Hooks without the key** — `onRequest()`, `onResponse()` and `onFailure()` for logs and metrics, and `debug()` masks the key as `key=***`.
- **Your own requests** — a method the SDK does not ship is one Saloon request away, sent with the key, the budget and SDK exceptions.
- **Test fakes** — `SteamFake` fakes every endpoint through the resource chain, with a factory per DTO and the failures Steam really sends.
- **Zero framework coupling** — plain Saloon over any `Sender` you hand it; a [Laravel bridge](https://docs.fkrzski.dev/laravel-steam-api-sdk) ships separately.

## Requirements

- PHP **8.5+**
- Saloon **4**, with its rate limit plugin **2.5.2+**

## Installation

<Steps>

1. Pull the package in:

   ```bash
   composer require fkrzski/php-steam-api-sdk
   ```

2. Keep your [Steam Web API key](https://steamcommunity.com/dev) out of the source tree, or
   skip it if the [anonymous endpoints](/php-steam-api-sdk/configuration#without-an-api-key)
   are all you need:

   ```dotenv title=".env"
   STEAM_API_KEY=your-steam-web-api-key
   ```

3. Build a connector from it, and reuse that one instance — it carries the key and
   the hooks you register:

   ```php title="steam.php" "$_ENV['STEAM_API_KEY']"
   use Fkrzski\SteamApiSdk\SteamConfig;
   use Fkrzski\SteamApiSdk\SteamConnector;

   $connector = new SteamConnector(new SteamConfig(
       apiKey: $_ENV['STEAM_API_KEY'],
   ));
   ```

</Steps>

<Aside type="tip" title="On Laravel?">
Skip the wiring — the [Laravel bridge](https://docs.fkrzski.dev/laravel-steam-api-sdk)
auto-discovers a `Steam` facade, reads the key from config, and shares the daily budget
through your cache store.
</Aside>

## Quickstart

```php
use Fkrzski\SteamApiSdk\ValueObjects\SteamId;

$summaries = $connector->users()->summaries([SteamId::fromSteamId64('76561198000000000')]);

echo $summaries[0]->personaName;
```

Every endpoint hangs off a resource named after its Steam interface — `players()`,
`users()`, `stats()`, `apps()`, `news()`, `webApi()` — and returns its typed result straight away.

## Versioning

The SDK follows [SemVer](https://semver.org/) from 1.0.0. A minor or patch release keeps:

- `SteamConfig` and its named arguments, and on `SteamConnector` the constructor, `$steamConfig`,
  the resources with their methods, `rateLimitBudget()`, and `onRequest()`, `onResponse()` and
  `onFailure()`.
- The request classes' constructors, public properties and `MAX_STEAM_IDS`, and the DTO each
  one returns.
- What you read off DTOs, hook payloads and exceptions: properties and their types, the
  exception hierarchy and codes, and the Steam method that opens a message.
- `SteamId`, the enums and `fromApiValue()` where they have one, and the `HasLanguage`,
  `SendsNoApiKey` and `SendsOptionalApiKey` contracts.
- `RateLimitBudget`'s `remaining()`, `wait()` and `waitAfter()` with the `Allowance` properties,
  and `UtcDayLimit::requests()`, a day limit on the counter of the default budget.
- The `SteamApiException` constructor, for [exceptions of your own](/php-steam-api-sdk/custom-requests#failures).
- The exception each [Steam answer](/php-steam-api-sdk/exceptions#how-statuses-are-mapped) maps to,
  and what a [sender has to honour](/php-steam-api-sdk/configuration#what-a-sender-has-to-honour).
  Following Valve when it changes an answer is a fix, and a minor may narrow an exception to a
  new subclass of it.
- `SteamFake`, its resource fakes and the factories under `Testing`.

Any release may change:

- Anything marked `@internal`: DTO constructors and `fromArray()`, the hook payload,
  `SteamSender`, `RateLimitBudget` and `Allowance` constructors, the exceptions' named
  constructors such as `fromLimit()`, `SteamApiException::naming()`, the `HasRequiredPaths`
  contract, and the `SteamApiRequest`,
  `SteamApiResponse`, `Http\Call`, `Http\RateLimiter` and `Http\ApiKeyMask` classes.
  Build DTOs and failures in tests with the [testing helpers](/php-steam-api-sdk/testing);
  PHPStan with bleeding edge reports a call from your code.
- Resource constructors; reach a resource through the connector.
- An exception's message after the method prefix.
- Saloon's lifecycle methods the connector and requests implement, such as `boot()`,
  `resolveEndpoint()` and `getRequestException()`.
- Limit names and the keys in a rate limit store, so a release may restart the counters once.

Saloon's own methods on the connector — `send()`, `pool()`, `withMockClient()`,
`getExceededLimit()` and the rest — follow Saloon's versioning, and the SDK keeps what it
documents on top of them. A new major of Saloon or its rate limit plugin comes in an SDK major,
a higher minimum PHP in a minor.
