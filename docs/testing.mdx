title: Testing
description: Fake the Steam Web API with SteamFake — build payloads from DTO factories, fake the failures Steam sends, and assert on the requests you send.
---

`Testing\SteamFake` is a Saloon [`MockClient`](https://docs.saloon.dev/testing/recording-responses)
that fakes each endpoint through the same resource chain your code calls. Attach it with
`withMockClient()`: no request leaves the machine, and the DTOs come from the payloads the
factories build.

## Faking responses

<Tabs syncKey="php-test-runner">
  <TabItem label="Pest">
    ```php title="tests/PlayerSummariesTest.php"
    use Fkrzski\SteamApiSdk\SteamConfig;
    use Fkrzski\SteamApiSdk\SteamConnector;
    use Fkrzski\SteamApiSdk\Testing\Factories\ISteamUser\PlayerSummaryFactory;
    use Fkrzski\SteamApiSdk\Testing\SteamFake;
    use Fkrzski\SteamApiSdk\ValueObjects\SteamId;

    it('reads the persona name off a summary', function (): void {
        $fake = new SteamFake()->users()->summaries(
            PlayerSummaryFactory::new()->personaName('Gabe')->online(),
        );

        $connector = new SteamConnector(new SteamConfig('test-key'))->withMockClient($fake);

        $summaries = $connector->users()->summaries([SteamId::fromSteamId64('76561198000000000')]);

        expect($summaries[0]->personaName)->toBe('Gabe');
    });
    ```
  </TabItem>

Each method registers the response under the request class its endpoint sends and hands the
fake back, so the chain moves resource by resource. Faking the same endpoint twice keeps the
second.

A method wrapping a collection takes as many factories as you want, and an empty call fakes an
empty result. The rest take exactly what their envelope carries: one container factory, a
plain number, a `SteamId` or a moment:

```php
$fake = new SteamFake()
    ->users()->summaries()                           // no players matched
    ->users()->friends($first, $second, $third)      // three friends
    ->players()->badges(PlayerBadgesFactory::new())  // the badges envelope
    ->players()->steamLevel(42)                      // a level, no factory
    ->stats()->currentPlayers(12_345)                // a head count, no factory
    ->webApi()->serverInfo(new DateTimeImmutable()); // Steam's clock, no factory
```

The fake swaps the HTTP client, not the connector, so a request that needs a key still raises
`ApiKeyNotConfiguredException` on a config [without one](/php-steam-api-sdk/configuration#without-an-api-key).
Give the test config any key: it never leaves the machine.

`new SteamFake()` also takes a map of request class → `MockResponse`, for a
[request of your own](/php-steam-api-sdk/custom-requests) or an answer the chain does not build,
and the map combines with a chain:

```php
use Saloon\Http\Faking\MockResponse;

$fake = new SteamFake([
    GetCmListRequest::class => MockResponse::make(['response' => ['serverlist' => []]]),
])->users()->summaries();
```

<Aside title="Why a method per endpoint">
No two endpoints agree on where the collection goes: `GetPlayerBans` puts it at the top level,
`GetFriendList` under `friendslist.friends`, `GetOwnedGames` under `response.games` beside the
`game_count` the SDK reads to decide whether the profile is public at all.
</Aside>

| `->stats()->userStats()` | `GetUserStatsForGameRequest` |

A `MockResponse` of your own needs the envelope the chain method builds: without it the call raises
`UnreadableResponseException`, except an empty `GetFriendListRequest` body, which reads as no
friends. A maintenance page in place of JSON raises it on every request:
`MockResponse::make('<html>maintenance</html>')`.

## DTO factories

Every DTO the SDK returns has a factory for the payload Steam sends, under
`Testing\Factories` and the interface whose endpoint returns it, as the requests are.
`::new()` gives a complete, realistic record you can narrow:

```php
use Fkrzski\SteamApiSdk\Testing\Factories\ISteamUser\PlayerSummaryFactory;

PlayerSummaryFactory::new()->toArray();   // the raw payload
PlayerSummaryFactory::new()->make();      // the PlayerSummary DTO
```

Reach for `make()` when a test needs the DTO directly: seeding a repository, or exercising a
method that takes a `PlayerSummary` with no HTTP in the picture.

Named states cover the variations worth naming, and compose:

```php
PlayerSummaryFactory::new()->private();                      // hidden profile
PlayerSummaryFactory::new()->friendsOnly();                  // friends-only profile
PlayerSummaryFactory::new()->online()->inGame('730', 'CS2'); // online, in a game
PlayerBanFactory::new()->vacBanned(2)->communityBanned();
OwnedGameFactory::new()->withAppInfo()->neverPlayed();
RecentlyPlayedGamesFactory::new()->nothingPlayed();
BadgeFactory::new()->communityItem()->withoutApp();
CommunityBadgeQuestFactory::new()->incomplete();
PlayerAchievementFactory::new()->locked();
UserStatsFactory::new()->empty();
SchemaAchievementFactory::new()->hidden()->withoutDescription();
GameSchemaFactory::new()->empty();
AppVersionCheckFactory::new()->outOfDate(requiredVersion: 10828683);
GameServerFactory::new()->insecure()->withoutSpectatorPort();
SdrPointOfPresenceFactory::new()->withoutRelays();
NewsItemFactory::new()->communityAnnouncement()->internalUrl()->withoutAuthor();
WebApiMethodFactory::new()->post()->withoutDescription();
WebApiParameterFactory::new()->optional()->emptyDescription();
```

`private()` withholds everything Steam does on a hidden profile, the creation date included,
so the summary carries a null `timeCreated`. `friendsOnly()` withholds the same and reads back
as `CommunityVisibility::FriendsOnly`.

`empty()` on `GameSchemaFactory` builds what an app publishing no schema answers with: Steam
drops every key, so the DTO comes back with a null `gameName` and two empty lists. `unnamed()`
on `GameSchemaFactory` and `SchemaStatFactory` sends the empty name Steam really sends, which
the DTO reads back as null.

`withoutSpectatorPort()` sends the `0` Steam sends for a server without SourceTV and
`withoutAuthor()` the `''` of a post without a byline; the DTO reads both as null.
`withoutRelays()` drops the key the way Steam does. A Web API description goes missing both
ways: `withoutDescription()` drops the key, as Steam does on most methods, `emptyDescription()`
sends the `''` some parameters carry, and the DTO reads either as null.

`state()` covers the rest, raw payload keys merged over the defaults:

```php
PlayerSummaryFactory::new()->state(['profileurl' => 'https://example.test/']);
```

The container factories take the item factories:

```php
UserStatsFactory::new()->stats(
    UserStatFactory::new()->name('DBD_KillerSkulls')->value(1200),
);

PlayerAchievementsFactory::new()->achievements(
    PlayerAchievementFactory::new(),
    PlayerAchievementFactory::new()->locked(),
);

GameSchemaFactory::new()->stats(
    SchemaStatFactory::new()->apiName('DBD_KillerSkulls'),
)->achievements(
    SchemaAchievementFactory::new()->apiName('ACH_ESCAPE'),
);

SdrConfigFactory::new()->pointsOfPresence(
    SdrPointOfPresenceFactory::new()->code('waw')->latitude(52.23)->longitude(21.01)->relays(
        SdrRelayFactory::new()->ipv4('155.133.240.10')->ports(27015, 27060),
    ),
);

WebApiInterfaceFactory::new()->name('ISteamUser')->methods(
    WebApiMethodFactory::new()->name('GetPlayerSummaries')->version(2)->parameters(
        WebApiParameterFactory::new()->name('steamids'),
    ),
);
```

A point of presence carries its code into the key of `pops` rather than the payload, and
`latitude()` and `longitude()` write `geo` in Valve's `[longitude, latitude]` order, so set
them by name rather than through `state()`.

`RecentlyPlayedGamesFactory::games()` syncs `total_count` to what it lists, so `totalCount()`
comes after it to fake the window Steam counted more games in than it returned.
`AppNewsFactory::items()` and `total()` work the same way, for page one of many:

```php
RecentlyPlayedGamesFactory::new()->games(
    RecentlyPlayedGameFactory::new()->name('Dead by Daylight')->playedRecently(240),
)->totalCount(12);

AppNewsFactory::new()->items(
    NewsItemFactory::new()->title('Patch notes'),
)->total(250);
```

## More than 100 Steam IDs

`summaries()` and `bans()` cut a list [over 100 IDs](/php-steam-api-sdk/guide#more-than-100-steam-ids)
into requests of 100. On the fake, each request gets the faked players it asks for, so 150 IDs
against 150 faked players return each player once:

```php
$fake = new SteamFake()->users()->summaries(...array_map(
    fn (SteamId $steamId): PlayerSummaryFactory => PlayerSummaryFactory::new()->steamId($steamId),
    $steamIds,
));

$connector->withMockClient($fake)->users()->summaries($steamIds); // 150 summaries, 2 requests
```

A request that asks for none of the faked players gets the ones no request has had yet, so a
test that never matched the IDs keeps working. A player handed out that way doesn't come back,
even to a request asking for it, so a call over 100 IDs never repeats one, and once each has
come back, a call matching nobody gets `[]`.

## Faking paged news

`->news()->newsFeed()` takes a whole feed rather than one page: the items newest first, each
with its own `id()`. It answers every `GetNewsForAppRequest` with the page Steam would send for
its `count`, 20 without one, and `endDate`, for code that pages through older news:

```php
$fake = new SteamFake()->news()->newsFeed(...$items);

$page = $connector->news()->appNews(appId: 440, count: 20);
$older = $connector->news()->appNews(appId: 440, count: 20, endDate: array_last($page->items)->publishedAt);
```

Steam counts `endDate` in, so the next page opens on the item the last one ended with.
`feeds`, `tags` and `maxlength` are not applied, so pass only the items a filtered feed would
hold.

## Faking failures

Each endpoint names the refusals Steam answers it with beside it, so the test gets the
exception the SDK raises for that endpoint:

| Chain | Raises |
| --- | --- |
| `->users()->friendsNotPublic()` | `ProfileNotPublicException` |
| `->users()->groupsNotPublic()` | `ProfileNotPublicException` |
| `->players()->ownedGamesNotPublic()`, and the same on the other four IPlayerService endpoints | `ProfileNotPublicException` |
| `->stats()->userStatsNotPublic()` | `ProfileNotPublicException` |
| `->stats()->achievementsUnavailable()` | `StatsUnavailableException` |
| `->stats()->currentPlayersAppNotFound()` | `AppNotFoundException` |
| `->stats()->schemaAppNotFound()` | `AppNotFoundException` |
| `->stats()->globalAchievementsUnavailable()` | `StatsUnavailableException` |
| `->users()->vanityUrlNotFound()` | `SteamUserNotFoundException` |
| `->apps()->upToDateCheckUnavailable()` | `AppVersionUnavailableException` |
| `->apps()->serversAtAddressInvalid()` | `InvalidServerAddressException` |
| `->apps()->serversAtAddressRefused()` | `SteamApiException` |
| `->apps()->sdrConfigAppNotFound()` | `AppNotFoundException` |
| `->news()->appNewsUnavailable()` | `AppNewsUnavailableException` |
| `->webApi()->supportedApiListInvalidKey()` | `InvalidApiKeyException` |
| `->invalidApiKey()` | `InvalidApiKeyException` |
| `->connectionFailed()` | `SteamConnectionException` |
| `->tooManyRequests()` | `SteamRateLimitException` |

    it('surfaces a private friend list', function (): void {
        $connector = new SteamConnector(new SteamConfig('test-key'))
            ->withMockClient(new SteamFake()->users()->friendsNotPublic());

        $connector->users()->friends($steamId);
    })->throws(ProfileNotPublicException::class);
    ```
  </TabItem>
  <TabItem label="PHPUnit">

    use Fkrzski\SteamApiSdk\Exceptions\ProfileNotPublicException;

    $connector = new SteamConnector(new SteamConfig('test-key'))

    $this->expectException(ProfileNotPublicException::class);

    $connector->users()->friends($steamId);
    ```
  </TabItem>
</Tabs>

`->invalidApiKey()`, `->connectionFailed()` and `->tooManyRequests()` sit on the fake itself
and answer every request that has no response of its own, so a chain can fake one endpoint and
let the rest fail.

Every failure above but `connectionFailed()` and `tooManyRequests()` sends the status and body
Steam was captured sending, byte for byte, so code that reads the response itself through
`body()` or `object()` sees what Steam sends.

A hidden profile looks different on every endpoint. `friendsNotPublic()` is a `401` with an
empty JSON object, and `groupsNotPublic()` a `403` carrying `Private profile`. The five
IPlayerService ones are a **`200`** whose only tell is the missing key the endpoint reads
(`game_count` for `ownedGames()`, `player_level` for `steamLevel()` and `badges()`).
`userStatsNotPublic()` is a `400` with an empty JSON object. `achievementsUnavailable()` is the `400`
carrying `Requested app has no stats`, which Steam sends for a hidden profile too, so the SDK
raises `StatsUnavailableException` rather than guess.

The endpoints taking an app ID refuse it four more ways: `currentPlayersAppNotFound()` is a
`404` carrying `result: 42`, `schemaAppNotFound()` a bare `400`, `globalAchievementsUnavailable()`
a `403` with an empty JSON object for a game with no achievements and an unknown one alike, and
`sdrConfigAppNotFound()` a `500` carrying `Failed to get appinfo`, raised before the connector
can retry it. `appNewsUnavailable()` is the empty `403` again, which `GetNewsForApp` answers an unknown app
and one whose news it does not publish with.

`UpToDateCheck` and `GetServersAtAddress` refuse with a `200` and `success: false`.
`upToDateCheckUnavailable()` covers an unknown app and one without server versions alike, and
`serversAtAddressRefused()` is the per-IP refusal the SDK raises as the root
`SteamApiException`, so only the method's name says which failure it is.

`invalidApiKey()` fakes the `403` page Steam rejects a key with. `GetCommunityBadgeProgress`
sends the same page on a `401`, which raises the same `InvalidApiKeyException`.
`invalidApiKey()` is for requests that send the key, the only ones Steam rejects a key on. A
request sent without it still gets the faked `403`: `GetNewsForApp` and
`GetGlobalAchievementPercentagesForApp` raise their own refusal from it, the rest
`InvalidApiKeyException`.
`GetSupportedAPIList` answers a JSON `403` with an empty interface list instead of the HTML
page, and `supportedApiListInvalidKey()` fakes that.

`tooManyRequests()` raises `SteamRateLimitException` the way Steam's own `429` does, and starts
the [cool-down](/php-steam-api-sdk/rate-limiting#after-a-429) with it: every later request sent
the same way is refused locally, before the fake can answer, for `Retry-After` seconds when you
pass them. A `429` on a keyed request leaves requests
[sent without the key](/php-steam-api-sdk/rate-limiting#requests-sent-without-the-key) alone, and
the other way round.
`TooManySteamIdsException` comes from a request constructor given more than 100 IDs, and a
spent local budget from the limiter before any response exists, so the fake has neither.

## Rate limits in tests

The default `MemoryStore` keeps its backing array static, so the budget and the lock after a
faked `429` outlive the test, and the next one using the same key fails with
`SteamRateLimitException`. `new SteamFake()` clears the store, so a test that builds its fake
first starts with a fresh budget and no lock.

A test on a plain `MockClient`, or one sending before it builds the fake, still needs the store
cleared in its setup. A [store of your own](/php-steam-api-sdk/rate-limiting#sharing-the-budget-across-processes)
is yours to reset:

<Tabs syncKey="php-test-runner">
  <TabItem label="Pest">
    ```php title="tests/Pest.php"
    use Saloon\RateLimitPlugin\Stores\MemoryStore;

    pest()->beforeEach(fn () => MemoryStore::clear());
    ```
  </TabItem>
  <TabItem label="PHPUnit">
    ```php title="tests/TestCase.php"
    use Saloon\RateLimitPlugin\Stores\MemoryStore;

    protected function setUp(): void
    {
        parent::setUp();

        MemoryStore::clear();
    }
    ```
  </TabItem>
</Tabs>

<Aside type="caution" title="One fake per test">
The store is shared by every connector in the process, so a second `SteamFake` built halfway
through a test resets the counters of the first one's connector too.
</Aside>

## Retries

The fake keeps the [`tries`](/php-steam-api-sdk/configuration#retries) the connector's config
sets, so a faked `5xx` is retried and every attempt is counted. `retryInterval` is `0` unless
the test config sets one, and Saloon sleeps for real between tries when it does:

```php
use Saloon\Http\Faking\MockResponse;

$fake = new SteamFake([
    GetPlayerSummariesRequest::class => MockResponse::make(status: 503),
]);

$connector = new SteamConnector(new SteamConfig('test-key', tries: 3))->withMockClient($fake);

try {
    $connector->users()->summaries([$steamId]);
} catch (SteamApiException) {
    // raised once the third attempt fails too
}

$fake->assertSentCount(3);
```

`connectionFailed()` is retried the same way, but Saloon throws it before recording a
response, so the recorded traffic and the assertions never see the attempt. Assert on the
exception.

## Asserting

`SteamFake` is a `MockClient`, so Saloon's assertions run on it directly:

```php
$fake->assertSent(GetPlayerSummariesRequest::class);
$fake->assertNotSent(GetPlayerBansRequest::class);
$fake->assertSentCount(1);
$fake->assertSentCount(1, GetPlayerSummariesRequest::class);
$fake->assertNothingSent();

$fake->assertSentInOrder([
    ResolveVanityUrlRequest::class,
    GetPlayerSummariesRequest::class,
]);
```

`assertSent()` and `assertNotSent()` also take a closure, for the request's query, body or
headers when the class alone isn't enough:

```php
$fake->assertSent(
    fn (GetPlayerBansRequest $request): bool => $request->steamIds === $ids,
);
```

`getRecordedResponses()` returns the Saloon `Response` objects in the order they came back,
and `getLastRequest()` and `getLastResponse()` the last exchange, or `null` when nothing was
sent.
